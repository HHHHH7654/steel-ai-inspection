# 04 核心业务流程

## 主业务链路

```text
图片或摄像头帧
  -> 前端体验校验
  -> 后端文件校验
  -> Mock 推理
  -> 定位框与置信度展示
  -> 人工确认 / 误检 / 漏检
  -> 浏览器本地追溯记录
```

## 单图检测

1. 用户选择或拖入一张 JPG/JPEG/PNG 图片。
2. 前端检查 MIME 类型和 10 MB 限制，生成本地预览。
3. 前端以 `multipart/form-data` 提交文件、阈值和来源。
4. 后端再次检查文件类型、文件后缀、空文件和大小。
5. Mock 服务返回模型信息、预测框、推理耗时和 `mock` 标识。
6. 前端在原图上叠加 SVG 定位框。
7. 用户给出人工复核结论，页面写入 LocalStorage。

## 批量检测

1. 用户选择最多 20 张图片。
2. 前端自动排除类型不符或大于 10 MB 的文件。
3. 每张有效图片独立调用后端接口。
4. 成功结果写入本地历史；校验失败图片会被统计，但不阻断已成功的图片。

当前批量功能是同步演示，不使用 Redis、Celery、消息队列或数据库。

## 摄像头单帧检测

1. 用户授权浏览器访问摄像头。
2. 页面播放本地视频预览，不持续上传视频。
3. 用户点击截帧，前端将当前画面转为 JPEG 文件。
4. JPEG 通过同一个上传接口提交。
5. 成功后进入单图结果页进行人工复核。

## 人工复核与困难样本候选

| 复核状态 | 当前行为 | 后续建议 |
| --- | --- | --- |
| 待复核 | 新结果默认状态 | 分配给质检人员 |
| 已确认 | 结果被人工认可 | 作为正式记录保存 |
| 误检 | 检测框不正确 | 进入困难样本候选池 |
| 漏检 | 应检出但未检出 | 补充标注并进入候选池 |

当前只在浏览器内统计。获得数据授权和数据库设计后，才能将其写入正式质量记录或训练集。
