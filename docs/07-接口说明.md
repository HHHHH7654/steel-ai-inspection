# 07 接口详细设计与联调规范

## 1. 文档信息

| 项目 | 内容 |
| --- | --- |
| 系统名称 | SteelVision 热轧钢带划痕检测与质量追溯平台 |
| 文档版本 | `V1.0-开发基线` |
| 接口前缀 | `/api/v1` |
| 当前运行模式 | `mock` |
| 适用范围 | 本地演示、前后端联调与接口验收 |

本文件只定义本次演示系统必须实现的接口。账号、数据库、对象存储、异步任务、实时推送以及真实模型接口不属于本次范围，不能由前端假设其存在。

## 2. 服务地址与通用约定

### 2.1 服务地址

| 环境 | 前端 | 后端 | API 文档 |
| --- | --- | --- | --- |
| 本地开发 | `http://localhost:5173` | `http://127.0.0.1:8000` | `http://127.0.0.1:8000/docs` |

前端通过 `NEXT_PUBLIC_API_BASE_URL` 配置后端根地址。路径示例中的 `/api/v1` 已包含版本前缀。

### 2.2 协议与编码

- 使用 HTTP（本地演示）；正式部署时必须改为 HTTPS。
- 所有 JSON 使用 UTF-8 和 `application/json`。
- 图片推理使用 `multipart/form-data`；不得手动设置包含 boundary 的 `Content-Type`，由浏览器 `FormData` 自动生成。
- 当前接口不使用 `{ success, message, data }` 包装，调用方以 HTTP 状态码判断请求结果。
- 当前接口无服务端 token 或权限校验。前端的演示登录状态不可作为 API 身份凭证。

### 2.3 响应时间与重试

- 单张 Mock 推理为同步请求；前端建议在 15 秒后提示“请求时间较长”，但不要自动重复提交。
- 上传类请求默认不自动重试，避免用户在未来切换为持久化接口时重复创建记录。
- 发生网络错误或 5xx 时由用户手动重试；按钮应在请求结束后恢复可用。

## 3. 数据类型与统一规则

| 名称 | 类型 | 规则 |
| --- | --- | --- |
| `record_id` | string / UUID | 本次推理响应的临时唯一标识；不是服务端持久化主键 |
| `created_at` | string / ISO 8601 | 使用带时区的服务端创建时间 |
| `threshold` | number | 0.10–0.95，最多保留两位小数 |
| `source` | string | 仅允许 `单图`、`批量`、`摄像头` |
| `confidence` | number | 0–1，前端显示为百分比时乘以 100 |
| `bbox` | object | `x1/y1/x2/y2` 为 0–100 百分比坐标 |
| `mode` | string | 当前固定 `mock`，页面必须显式显示 |

### 3.1 检测框坐标规则

`bbox` 相对原图宽高计算：

```text
left   = x1%
top    = y1%
width  = (x2 - x1)%
height = (y2 - y1)%
```

后端保证 `x1 < x2`、`y1 < y2` 且所有坐标在 0–100 内；前端接收异常坐标时不得渲染越界框，应将该预测标记为无效并显示通用提示。

### 3.2 通用错误对象

FastAPI 的业务错误至少具有 `detail` 字段：

```json
{
  "detail": "仅支持 JPG、JPEG 或 PNG 格式的图片。"
}
```

`422` 参数校验错误可能是 FastAPI 的字段错误数组。前端应优先展示首个字段的可读原因，不直接向用户展示内部字段路径或堆栈。

## 4. 接口一览

| 编号 | 方法 | 路径 | 是否必须 | 用途 |
| --- | --- | --- | --- | --- |
| API-01 | GET | `/health` | 是 | 检查后端是否可用 |
| API-02 | GET | `/api/v1/system/info` | 是 | 返回运行模式、版本和上传限制 |
| API-03 | POST | `/api/v1/inferences` | 是 | 单张图片文件校验与同步 Mock 推理 |

批量检测和摄像头检测都复用 API-03：批量页面逐文件调用，摄像头页面将用户主动截取的 JPEG 作为 `file` 上传。

## 5. API-01：健康检查

### 请求

```http
GET /health HTTP/1.1
Host: 127.0.0.1:8000
```

- 认证：不需要。
- 请求体：无。

### 成功响应：200

```json
{
  "status": "ok",
  "service": "steelvision-backend",
  "mode": "mock"
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `status` | string | 正常时固定为 `ok` |
| `service` | string | 服务标识 |
| `mode` | string | 当前固定为 `mock` |

### 前端处理

应用启动与工作台加载时调用一次。请求成功且 `status` 为 `ok` 时显示“后端已连接”；网络错误、非 2xx 或字段异常时显示“后端待连接”，但不阻止用户浏览静态页面。

## 6. API-02：运行能力概要

### 请求

```http
GET /api/v1/system/info HTTP/1.1
Host: 127.0.0.1:8000
```

- 认证：不需要。
- 请求体：无。

### 成功响应：200

```json
{
  "service": "steelvision-backend",
  "version": "0.2.0",
  "mode": "mock",
  "max_upload_bytes": 10485760,
  "accepted_content_types": ["image/jpeg", "image/png"]
}
```

| 字段 | 类型 | 前端用途 |
| --- | --- | --- |
| `service` | string | 调试信息，不建议作为页面主标题 |
| `version` | string | 模型/系统说明页展示 |
| `mode` | string | 展示 Mock 标识 |
| `max_upload_bytes` | integer | 换算为 MB 后用于上传说明与前端校验 |
| `accepted_content_types` | string[] | 生成文件类型提示，不替代后端校验 |

### 前端处理

页面可使用内置默认限制（JPG/JPEG/PNG、10 MB）先渲染；获取成功后用该响应覆盖展示配置。若获取失败，仍保留默认限制并显示后端状态异常。

## 7. API-03：创建单张推理请求

### 请求定义

```http
POST /api/v1/inferences HTTP/1.1
Host: 127.0.0.1:8000
Content-Type: multipart/form-data; boundary=---generated-by-browser
```

| 表单字段 | 类型 | 必填 | 约束 | 说明 |
| --- | --- | --- | --- | --- |
| `file` | file | 是 | JPG/JPEG/PNG；不超过 10 MB；非空 | 原始图片或摄像头截帧 |
| `threshold` | number | 是 | 0.10–0.95 | 置信度阈值 |
| `source` | string | 是 | `单图` / `批量` / `摄像头` | 本次输入来源 |

浏览器调用示例：

```ts
const formData = new FormData();
formData.append("file", file);
formData.append("threshold", threshold.toFixed(2));
formData.append("source", source);

const response = await fetch(`${apiBaseUrl}/api/v1/inferences`, {
  method: "POST",
  body: formData,
});
```

### 成功响应：200

```json
{
  "record_id": "2e6fbd30-5db4-4a62-b8e6-8a4f9b356a2f",
  "name": "steel-strip-001.jpg",
  "created_at": "2026-08-13T10:20:30+00:00",
  "model": {
    "name": "scratch-detector",
    "version": "mock-v0.1"
  },
  "predictions": [
    {
      "class_name": "Scratch",
      "confidence": 0.82,
      "bbox": { "x1": 24, "y1": 33, "x2": 78, "y2": 60 }
    }
  ],
  "inference_ms": 180,
  "threshold": 0.5,
  "source": "单图",
  "mode": "mock"
}
```

### 响应字段

| 字段 | 类型 | 必有 | 说明 |
| --- | --- | --- | --- |
| `record_id` | string | 是 | 单次结果标识，前端以它关联本地复核记录 |
| `name` | string | 是 | 原始文件名，仅用于展示 |
| `created_at` | string | 是 | 服务端生成时间 |
| `model.name` | string | 是 | 当前模型名称 |
| `model.version` | string | 是 | 当前模型版本 |
| `predictions` | array | 是 | 检测结果；允许为空数组 |
| `predictions[].class_name` | string | 是 | 当前类别为 `Scratch` |
| `predictions[].confidence` | number | 是 | 0–1 的置信度 |
| `predictions[].bbox` | object | 是 | 百分比坐标框 |
| `inference_ms` | integer | 是 | 后端本次处理耗时，单位毫秒 |
| `threshold` | number | 是 | 后端实际生效的阈值，应回显给前端 |
| `source` | string | 是 | 后端回显的输入来源 |
| `mode` | string | 是 | 当前固定 `mock` |

### 成功后的前端处理

1. 校验响应必要字段及坐标范围。
2. 以原图比例绘制预测框，并显示类别和置信度。
3. 初始化本地复核状态为 `待复核`，复核说明为空。
4. 将响应、来源、缩略图信息（如有）和复核信息写入 `steelvision.records.v1`。
5. 历史页可按 `record_id` 查看该记录；不得将其表述为服务端已保存记录。

### 业务错误

| HTTP 状态 | 触发条件 | `detail` 示例 | 前端行为 |
| --- | --- | --- | --- |
| 400 | 文件为空或读取后无内容 | `上传文件不能为空。` | 提示重新选择图片 |
| 413 | 文件超过上限 | `图片不能超过 10 MB。` | 提示压缩或更换图片 |
| 415 | MIME 类型、扩展名不符合 | `仅支持 JPG、JPEG 或 PNG 格式的图片。` | 提示支持的格式 |
| 422 | 缺字段、阈值范围错误、来源非法 | FastAPI 参数校验信息 | 还原默认阈值/来源并提示重试 |
| 500 | 未处理的服务端异常 | 不暴露内部细节 | 显示“服务异常，请稍后重试” |

## 8. 批量与摄像头的调用规则

### 8.1 批量

| 项目 | 规定 |
| --- | --- |
| 最大数量 | 20 张 |
| 调用方式 | 按文件逐张调用 API-03，不新增批量上传接口 |
| 并发要求 | 本次建议顺序执行，保证现场演示稳定；不得让某一张失败阻断后续文件 |
| 汇总字段 | 总数、待处理、处理中、成功、失败 |
| 单项记录 | 文件名、来源、状态、失败原因或 `record_id` |

### 8.2 摄像头单帧

| 项目 | 规定 |
| --- | --- |
| 输入来源 | `source=摄像头` |
| 文件名称 | 前端生成 `camera-YYYYMMDD-HHmmss.jpg` 格式即可 |
| 文件类型 | `image/jpeg` |
| 上传时机 | 仅用户点击“截帧并检测”后 |
| 不允许行为 | 持续上传视频帧、建立 WebSocket 视频流、后台静默调用摄像头 |

## 9. 前端本地复核对象（非后端接口）

为统一页面开发，本地记录以如下结构保存；这是浏览器数据结构，不要求后端提供 CRUD 接口：

```ts
type ReviewStatus = "待复核" | "已确认" | "误检" | "漏检";

type LocalInspectionRecord = {
  response: InferenceResponse;
  review_status: ReviewStatus;
  review_remark: string;
  reviewed_at: string | null;
  preview_url?: string;
};
```

规则：新记录默认为 `待复核`；说明最长 200 字；更新复核状态时同步写入 `reviewed_at`；本地解析或写入失败不影响当前检测结果展示，但要给出“本地记录未保存”的提示。

## 10. 联调与验收用例

| 用例 | 请求 / 操作 | 预期 |
| --- | --- | --- |
| I-01 | `GET /health` | 200，`status=ok`，`mode=mock` |
| I-02 | `GET /api/v1/system/info` | 200，返回 10 MB 和可接受 MIME 类型 |
| I-03 | 合法 JPG，阈值 `0.50`，来源 `单图` | 200，字段完整，坐标合法，`mode=mock` |
| I-04 | 合法 PNG，来源 `批量` | 200，`source` 原样回显 |
| I-05 | 空文件 | 400，含可读 `detail` |
| I-06 | 大于 10 MB 的图片 | 413，含可读 `detail` |
| I-07 | GIF、PDF 或伪造扩展名 | 415，含可读 `detail` |
| I-08 | 缺少阈值或阈值为 `0.99` | 422 |
| I-09 | 来源为 `视频流` | 422 |
| I-10 | 合法图片返回空 `predictions` | 200，前端展示正常空结果，可选择“漏检” |

## 11. 兼容性与变更规则

- 后端可将 Mock 服务替换为真实推理实现，但不得改变已定义字段名称、字段类型、坐标语义和错误码含义。
- 新增响应字段允许，删除或重命名已有字段须升级 API 版本并同步修改前端。
- 任何需要服务端持久化、用户身份、异步任务或实时事件的接口均须另行立项和设计，不得直接加入本接口版本。
