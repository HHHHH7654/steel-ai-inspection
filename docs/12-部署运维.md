# 12 部署运维

## 当前部署目标

当前项目面向本地演示。前端和后端需要分别部署：前端是 Next.js/Vinext 构建产物，后端是 FastAPI 服务。前端无法单独替代后端，因为图片校验和推理接口仍由后端提供。

## 本地运行端口

| 服务 | 默认地址 | 说明 |
| --- | --- | --- |
| 前端 | `http://localhost:5173` | 开发预览 |
| 后端 | `http://127.0.0.1:8000` | FastAPI 接口 |
| 后端文档 | `http://127.0.0.1:8000/docs` | Swagger UI |

## 前端构建

```powershell
cd frontend
npm.cmd run build
```

部署前应为 `NEXT_PUBLIC_API_BASE_URL` 配置可访问的 HTTPS 后端地址，并在后端将 CORS 白名单限制为该前端域名。

## 后端生产原则

- 使用固定 Python 环境或容器，不使用开发热重载。
- 由进程管理器负责重启和日志采集。
- 由反向代理提供 HTTPS、请求大小限制和访问日志。
- 引入持久化前先完成权限和数据保留期限设计。

## 部署检查清单

1. 前端 HTTPS 地址可以访问后端 HTTPS 地址。
2. CORS 只包含已知前端域名。
3. `/health` 不泄露配置或密钥。
4. 上传限制在代理和应用层保持一致。
5. 公开部署前替换演示账号为真实认证或关闭登录入口。
6. 数据、模型、日志和密钥都有存储与保留策略。

## 目前不应做的声明

在未接入数据、真实模型、认证、数据库和对象存储前，不应宣称系统已经具备生产可用的工业检测、账号权限、结果追溯或模型性能能力。
